# سيكرت كيلر (Secret Killer) 🕵️‍♂️🔍

لعبة تحقيق واستنتاج اجتماعي تفاعلية متعددة اللاعبين باللغة العربية. تدعم من 4 إلى 12 لاعباً مع قصص تفاعلية، أدوار سرية، محرك أدلة ديناميكي، جولات نقاش ومؤقتات، ونظام تصويت وكشف القاتل مع تقييم أداء المحققين.

---

## 📱 دليل وقائمة التحقق لنشر التطبيق على متجر Google Play

إذا كنت تخطط لتحزيم التطبيق (عبر TWA / Capacitor / Cordova / WebView) ونشره على **Google Play Console**، فيما يلي قائمة المتطلبات الأساسية والسياسات الإلزامية لضمان قبول التطبيق وتجنب الرفض:

### 1. سياسة الخصوصية وأمان البيانات (Privacy & Data Safety)
- [ ] **رابط سياسة الخصوصية (Privacy Policy URL)**: يجب توفير رابط صالح ومتاح للعامة على الإنترنت يوضح بوضوح البيانات التي يتم جمعها أو عدم جمعها.
- [ ] **قسم أمان البيانات (Data Safety Section)**: الإفصاح الدقيق في Google Play Console:
  - إذا كان التطبيق يعمل محلياً دون جمع بيانات خارجية: حدد أن التطبيق لا يجمع بيانات مستخدمين (`No data collected`).
  - إذا تم تفعيل تحليلات أو خدمات سحابية: حدد نوع البيانات والغرض منها وطريقة التشفير.
- [ ] **أذونات التطبيق (App Permissions)**: التأكد من عدم طلب أذونات حساسة غير مستخدمة في ملف `AndroidManifest.xml` (مثل الكاميرا أو جهات الاتصال أو الموقع ما لم تكن هناك ميزة فعلية تستخدمها).

### 2. تصنيف المحتوى والفئة العمرية (Content Rating - IARC)
- [ ] **استبيان IARC**: تعبئة استبيان المحتوى بدقة داخل Play Console.
- [ ] **المحتوى القصصي والجريمة الخيالية**: الإشارة إلى احتواء اللعبة على مواضيع تحقيق وجرائم خيالية بدون مشاهد عنف حية أو محتوى غير لائق.
- [ ] **الفئة العمرية المستهدفة**: تحديد الفئة العمرية المناسبة (عادةً **+12 أو +16** لألعاب الاستنتاج والغموض).

### 3. المعايير التقنية وجودة الأداء (Technical Standards)
- [ ] **حزمة التطبيق (Android App Bundle - .aab)**: رفع ملف بصيغة `.aab` موقع بمفتاح توقيع صالح (Keystore).
- [ ] **مستوى Target SDK**: استهداف أحدث إصدار من أندرويد يطلبه جوجل (حالياً **Target SDK 34 / Android 14+**).
- [ ] **معالجة زر الرجوع (Back Navigation)**: التأكد من أن الضغط على زر الرجوع في الهاتف يتنقل بسلاسة بين شاشات اللعبة دون إغلاق التطبيق فجأة أو التسبب في تجميد الشاشة.
- [ ] **التجاوب واستقرار العرض**: التحقق من ظهور واجهة اللعبة بشكل منسق على مختلف أحجام الشاشات (الهواتف، الأجهزة اللوحية، الهواتف القابلة للطي) بدون اقتطاع نصوص أو تداخل عناصر.
- [ ] **نسبة الاستقرار (Crash & ANR Rate)**: التأكد من اجتياز اختبارات تقرير ما قبل الإطلاق (Pre-launch Report) بنسبة أخطاء أقل من 1.09%.

### 4. سياسات الوصول والحسابات (App Access)
- [ ] **الوصول للعبة (App Access Section)**: تحديد أن جميع وظائف التطبيق متاحة مباشرة دون الحاجة لبيانات تسجيل دخول خاصة، أو تقديم حساب تجريبي لفريق المراجعة في حال إضافة نظام تسجيل مستقبلاً.
- [ ] **عدم وجود أزرار معطلة أو شاشات وهمية**: التأكد من اكتمال كافة الأزرار والروابط في الواجهة دون وجود نصوص مؤقتة (Lorem Ipsum) أو وظائف لا تستجيب.

### 5. متطلبات الاختبار لحسابات المطورين الفردية (Closed Testing)
- [ ] **اختبار الـ 20 مختبراً (للحسابات الشخصية المنشأة بعد نوفمبر 2023)**: إجراء اختبار مغلق (Closed Track) بمشاركة 20 مختبراً على الأقل لمدة 14 يوماً متواصلة قبل التقديم لطلب النشر على الإنتاج (Production).

### 6. أصول صفحة المتجر (Store Listing Assets)
- [ ] **أيقونة التطبيق عالية الدقة**: أبعاد 512 × 512 بكسل (PNG 32-bit).
- [ ] **الرسم المميز (Feature Graphic)**: أبعاد 1024 × 500 بكسل (JPG أو PNG بدون شفافية).
- [ ] **لقطات الشاشة (Screenshots)**: من 2 إلى 8 لقطات شاشة واضحة للهاتف (بنسبة 16:9 أو 9:16)، وتوضيح تدفق اللعبة الفعلي (شاشة القصص، توزيع الأدوار، جولة النقاش، وكشف القاتل).
- [ ] **الوصف القصير والطويل**: كتابة وصف دقيق وجذاب خالٍ من الكلمات الترويجية المضللة أو حشو الكلمات المفتاحية.

## 🛠️ البناء والتشغيل محلياً

```bash
# تثبيت الاعتماديات
npm install

# تشغيل خادم التطوير
npm run dev

# فحص الأخطاء البرمجية
npm run lint

# بناء نسخة الإنتاج
npm run build
```

## 📁 بنية المشروع الرئيسية

- `src/components/`: شاشات وواجهات اللعبة (القصص، توزيع الأدوار، الأدلة، التصويت، والنتائج).
- `src/engine/`: محرك اللعبة، تخصيص الشخصيات، ونظام كشف الأدلة والتبعيات.
- `src/stories/`: بيانات وحلقات القصص المحبوكة.
- `docs/`: التوثيقات الفنية وقوائم التحقق.
